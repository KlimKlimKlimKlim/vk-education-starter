# Практическое задание 8 — Retrofit

Решение находится в ветке `homework-8-retrofit`, основанной на `homework-7-hilt`.

## Что реализовано

- `AppsApi`: `suspend GET /catalog` и `suspend GET /{id}` с `@Path`.
- `CatalogAppDto`, `AppDetailsDto` и преобразования в domain через `AppMapper`.
- `AppsRepositoryImpl.getApps()` обращается к API, сохраняет полученный каталог в памяти и возвращает domain-модели. При сетевой ошибке локальный каталог не подставляется.
- `AppListViewModel` вызывает suspend-репозиторий из `viewModelScope`; UI показывает загрузку, данные, пустой каталог или ошибку с кнопкой «Повторить».
- Hilt `NetworkModule`: OkHttp, Retrofit с Gson, AppsApi. Base URL с завершающим `/`: `http://185.103.109.134/`.
- `INTERNET` в манифесте; HTTP разрешён только для учебного IP через network security config.
- Иконки из `iconUrl` загружаются Coil с локальным placeholder/error изображением.
- `getRemoteAppDetails(id)` реализован и маппит подробный ответ, но **не вызывается ни из одной ViewModel/Compose** — по заданию интегрировать его пока не нужно.
- Старый экран карточки сохранён: показывает выбранные данные каталога из памяти, без выдуманных разработчика/возраста/размера и без обращения за подробностями. Витрина использует первые 9 элементов каталога. После гибели процесса карточка восстанавливается повторной загрузкой только каталога.
- База данных/Room не добавлялись: в пунктах этого задания требуется только сеть.

## Расхождение сервера и задания

Проверка сервера 7 ноября 2026:

- `GET http://185.103.109.134/catalog` → HTTP 200, JSON-массив из 41 приложения; поля `id`, `name`, `description`, `category`, `iconUrl`.
- `GET http://185.103.109.134/fa2e31b8-1234-4cf7-9914-108a170a1b01` → HTTP 404.
- `GET http://185.103.109.134/82ea6f63-2b2a-43e1-b54c-ec62e6e27229` → HTTP 404.
- `GET http://185.103.109.134/catalog/fa2e31b8-1234-4cf7-9914-108a170a1b01` → HTTP 200, подробный объект; сервер присылает скриншоты в `screenshotUrlList`.

В практическом репозитории тоже используется `@GET("catalog/{id}")`:
https://github.com/maltsevmicyou/VkEducation/blob/8cc0830a2f6f97b8888717490fb3fcf8df9273e7/app/src/main/java/io/mmaltsev/vkeducation/data/appdetails/AppApi.kt

**В решении оставлен требуемый в задании `@GET("{id}")`**, без скрытой подмены пути и fallback. Когда понадобится интеграция подробностей, нужно уточнить путь у преподавателя. Схема подробного DTO проверена по работающему `/catalog/{id}`, `screenshotUrlList` и альтернативное имя `screenshots` поддержаны аннотацией Gson.

## Проверки

В этой среде выполнены: HTTP-проверки реального сервера, разбор его JSON, проверка XML/TOML, `git diff --check` и статическая проверка направлений зависимостей/отсутствия вызова подробного API из UI.

Добавлены/обновлены unit-тесты: Retrofit с MockWebServer (пути обоих GET, JSON, HTTP 404), репозиторий (сеть, mapper, отсутствие fallback, подробности не вызываются карточкой), ViewModel (загрузка, ошибка, повтор, сохранение состояния, восстановление карточки из каталога). JSON fixtures — тестовые данные с полями и типами реальных ответов; тексты и URL изображений заменены тестовыми.

**Сборка, тесты и Lint НЕ выполнены:** `bash ./gradlew :app:testDebugUnitTest --no-daemon` останавливается до запуска Gradle: `JAVA_HOME is not set and no 'java' command could be found in your PATH`. Android SDK в среде также отсутствует. Успешное прохождение не заявляется. Instrumented smoke-тесты обновлены под сетевой каталог; требуют доступности сервера и проверенных на дату записи названий приложений.

Локальная проверка из Android Studio с установленными JDK/SDK:

```powershell
git fetch origin
git switch homework-8-retrofit
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:assembleDebugAndroidTest :app:lintDebug
```

## Самопроверка на телефоне

1. Включить интернет, запустить приложение: после индикатора появятся `QuickNote`, `Calmalist`, `FitRiver` и остальные записи сервера (а не прежние 9 локальных приложений).
2. Прокрутить каталог: проверить название, описание, категорию и иконки. Количество записей берётся из ответа, а не фиксировано в коде.
3. Повернуть экран после загрузки: данные должны сохраниться, повторный GET не должен запускаться. Проверить через Android Studio Network Inspector.
4. Нажать toolbar и повернуть экран: старый Snackbar не должен повториться.
5. Открыть приложение: карточка должна показывать выбранное приложение, витрина — 3 страницы по 3 элемента при наличии минимум 9 записей. В Network Inspector не должно быть запроса `/{id}`.
6. Отключить интернет, полностью остановить приложение и открыть заново: после тайм-аута должна быть ошибка и «Повторить», а не локальный каталог. Уже открытый экран имеет данные в памяти, поэтому простого отключения интернета недостаточно для этого сценария.
7. Включить интернет и нажать «Повторить»: каталог должен загрузиться.
8. `/{id}` вручную в UI не проверяется — метод пока не подключён, а сервер по указанному пути возвращает 404 (см. выше).
